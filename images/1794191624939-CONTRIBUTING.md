# Contributing to Demouli

Demouli turns a structured demo script into an approved execution plan, then records that plan and keeps the named snapshots declared in the script. Read [README.md](./README.md) for the product scope and [Tech.md](./Tech.md) for the architecture before changing behavior.

## Setup

Python 3.12 or newer is required.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

Optional extras match capabilities that are not needed to validate or plan a script:

```bash
pip install -e ".[ui]"       # PySide6 result window
pip install -e ".[browser]"  # Playwright
pip install -e ".[vision]"   # OpenCV
pip install -e ".[llm]"      # instructor
```

## Checks

Run the tests from the repository root:

```bash
pytest
```

The example project under `examples/ecommerce` is the fixture used by the CLI tests.

```bash
demouli validate examples/ecommerce
demouli plan examples/ecommerce --out output/plan.json
demouli approve output/plan.json
```

`output/` is gitignored. `validate` checks references. `plan` writes a structural plan and does not call a model. `approve` records approval beside the plan file and does not start execution.

## Layout

Application code lives in `app/`.

| Path | Responsibility |
|---|---|
| `app/domain` | Environment, actor, application, script, action, and manifest models |
| `app/config` | YAML loading and reference checks |
| `app/planning` | Structural planning, and the LLM revision boundary |
| `app/workflow` | The explicit state machine |
| `app/execution` | The execution engine and the automation adapter |
| `app/recording` | FFmpeg command construction |
| `app/snapshots` | Session directories and the manifest |
| `app/events` | JSONL event logs |
| `app/review` | The session result window |
| `app/cli.py` | `validate`, `plan`, `approve`, and `review` |

Domain models stay independent of Playwright, FFmpeg, and PySide6. Those libraries are imported only at the edge that uses them.

## Boundaries

Keep these decisions intact when extending the foundation:

- A script step names an actor that was configured ahead of time. Planning must not reassign that actor's session or window.
- A `capture` on a step becomes its own action after that step. It is not a second way to take arbitrary screenshots.
- The execution engine follows the approved plan. Retry exhaustion pauses the workflow. It does not replan.
- Result review publishes or sets aside files that already exist. It does not change the approved plan or re-enter execution.
- Diagnostic images taken after a failure stay out of the published manifest.

Playwright execution, the FFmpeg process, and the result-line gestures are boundaries, not finished behavior. Extend those modules instead of folding that work into the domain models or the state machine.

## Tests

Add or update tests in `tests/` for parser, validation, planning, and state transitions. Prefer a fake automation adapter over launching a browser. A change to the action schema or the workflow states should include a test that shows the new path and one that rejects an illegal transition.
